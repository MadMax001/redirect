## Сервис перенаправления обращения
Клиентская точка входа: /v1/redirect?p1=...&p2=...&p3=...

Перенаправление происходит на основании двух GET-параметров p1 и p2. Происходит дешифрация ссылки из этих параметров 
на основании ключа, указанного в переменной окружения **ENCRYPTION_KEY**. Параметр p3 - внешний идентификатор запроса, формируемый в ГПБ.

Используется симметричное шифрование с применением трансформации трансформация AES/GCM/NoPadding. 
Параметр p1 содержит зашифрованную ссылку, на которую происходит перенаправление, 
параметр p2 - представляет собой инициализационный вектор. 
В случае невозможности расшифровать перенаправление происходит на ссылку, указанную в **redirect.errorUrl**

Все обращения фиксируются в БД.

### Профилирование
Предусмотрены 2 профиля: **prod** и **dev**, задаются переменной окружения **APP_PROFILE**. Основные отличия:
Для end-point /v1/redirect для профиля **prod** происходит перенаправление на ссылку, для профиля **dev** - возврат текстовой информации, содержащей gpb-id и расшифрованную ссылку.

### Healthcheck
Для проверки работоспособности сервиса внешними сервисами-оркестраторами используется end-point /e67d4c74-dfcd-4c24-94f9-7540d4d07f3b/check.
Для успешного запроса необходима basic-авторизация. Имя пользователя и пароль задается переменными окружения **APP_USER** и **APP_PASSWORD**
